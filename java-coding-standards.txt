                  数科业务 Java 编码规范速查（简版）
        源自技能 dtazziboot-java-coding-standards（对齐阿里巴巴嵩山版 + JDK21）

本文件为 Java 编码规范要点速查，适用于代码生成、单元测试编写、模块开发
与代码规范自检。完整条文见技能 references/ 目录各篇规约。

--------------------------------------------------------------------------------
一、命名规范（naming.md）
--------------------------------------------------------------------------------
1. 类名：UpperCamelCase，如 UserService、OrderController。
2. 方法名/变量名：lowerCamelCase，如 getUserById、maxStockCount。
3. 常量名：全大写，下划线分隔，如 MAX_STOCK_COUNT、CACHE_EXPIRE_SEC。
4. 包名：全小写，连续单词直接拼接，禁止下划线/大写，如 com.alibaba.order。
5. 抽象类用 Abstract/Base 开头；异常类用 Exception 结尾；测试类以 Test 结尾。
6. 数组定义：类型与中括号紧挨，如 int[] arr，禁止 String args[]。
7. Boolean 型变量名禁止以 is 前缀开头（避免 RPC 序列化字段名歧义）。

--------------------------------------------------------------------------------
二、常量与魔法值（constants.md）
--------------------------------------------------------------------------------
1. 【强制】不允许出现魔法值（未经定义的常量），必须定义为有语义的常量。
2. long 赋值使用大写 L，禁止小写 l（避免与 1 混淆）：long id = 2L。
3. 依赖固定顺序的常量，不要依赖枚举 ordinal，应显式赋值。

--------------------------------------------------------------------------------
三、格式规约（formatting.md）
--------------------------------------------------------------------------------
1. 缩进 4 空格，禁止 Tab。
2. 单行字符数上限 120，超出换行。
3. 大括号：左括号不换行，右括号独占一行；空代码块可简写为 {}。
4. 二元运算符前后各加一个空格；if/for/while 与括号间加一个空格。
5. 方法参数间逗号后加空格。

--------------------------------------------------------------------------------
四、OOP 规约（oop.md）
--------------------------------------------------------------------------------
1. 【强制】浮点数比较与金额运算禁止使用 == 或基本类型，使用 BigDecimal。
   - 比较：BigDecimal.compareTo(b) == 0，禁止 equals（1.0 与 1.00 不等）。
   - 构造：用 String 入参 new BigDecimal("0.1")，禁止 new BigDecimal(0.1)。
2. 【强制】覆写方法必须加 @Override 注解。
3. 【强制】equals 方法必须同时覆写 hashCode，保证相等对象哈希一致。
4. 所有 POJO 类属性必须使用包装类型（Integer/Long 等），方法内局部变量可用基本类型。

--------------------------------------------------------------------------------
五、集合与 Stream（collections.md）
--------------------------------------------------------------------------------
1. 转换集合时必须判空，避免 NPE；可用 CollectionUtils.isEmpty / Optional。
2. 遍历集合时禁止在 foreach 中直接 add/remove 元素，应使用 Iterator.remove。
3. Stream 中禁止在 forEach 里做副作用赋值，结果收集到集合再处理。
4. HashMap 初始化指定容量，减少扩容：new HashMap<>(expectedSize / 0.75 + 1)。

--------------------------------------------------------------------------------
六、并发规约（concurrency.md）
--------------------------------------------------------------------------------
1. 线程资源必须通过线程池提供，禁止显式 new Thread。
2. 线程池必须使用 ThreadPoolExecutor 显式构造，禁止 Executors 工厂方法
   （避免无界队列导致 OOM）。
3. SimpleDateFormat 非线程安全，禁止定义为 static 共享变量；
   使用 DateTimeFormatter（线程安全）或 ThreadLocal 包装。
4. 对多线程访问的共享变量必须加 volatile 或使用同步机制保证可见性。

--------------------------------------------------------------------------------
七、异常处理（exception-logging.md）
--------------------------------------------------------------------------------
1. 【强制】可预检的 RuntimeException 不应通过 catch 处理（如 NPE），应提前判空。
2. 【强制】enum.valueOf() 必须捕获 IllegalArgumentException。
3. 【强制】异常不得用于流程控制/条件控制。
4. 【强制】catch 需区分稳定代码与非稳定代码，分类型处理，禁止大段 try-catch。
5. 【强制】捕获异常必须处理，禁止吞掉异常；最外层需转为用户可理解的内容。
6. 【强制】事务场景中 catch 后若需回滚，必须手动回滚事务。
7. 【强制】finally 块必须关闭资源；JDK7+ 优先使用 try-with-resources。
8. 【强制】禁止直接抛出 Exception/RuntimeException/Throwable，应使用业务异常类。
9. 方法返回值可以为 null 时，调用方必须做 NPE 防御。

--------------------------------------------------------------------------------
八、日志规约（exception-logging.md）
--------------------------------------------------------------------------------
1. 日志门面使用 SLF4J，禁止直接使用 Log4j/Logback API。
2. 【强制】日志使用占位符而非字符串拼接：
     log.info("userId={}, action={}", userId, action);
3. 【强制】异常日志必须打印完整堆栈：log.error("msg", e)，禁止 log.error(e.getMessage())。
4. 生产环境禁止 debug 日志；debug 前必须做 isDebugEnabled 判断。
5. 日志应具备可追溯性：含 traceId/userId/关键业务字段。

--------------------------------------------------------------------------------
九、注释规约（comments.md）
--------------------------------------------------------------------------------
1. 类/公共方法必须有 Javadoc，说明用途、参数、返回值、异常。
2. 注释应解释"为什么"，而非复述代码；过时注释及时删除。
3. 半成品代码用 // TODO 标注并附责任人；禁止遗留无主 TODO。
4. 注释的双斜线与内容间留一个空格。

--------------------------------------------------------------------------------
十、单元测试（unit-testing.md）—— 每个模块必读
--------------------------------------------------------------------------------
1. 遵循 FIRST 原则：Fast、Independent、Repeatable、Self-validating、Timely。
2. 【强制】生成测试前必须完整阅读被测类源码，理解分支与异常路径。
3. 【强制】检索存量测试：已有则补充场景，遵循既有命名风格与测试基类。
4. 技术栈跟随项目：先扫 pom.xml 与已有测试，>80% 用同一框架则不引入新库。
5. 测试方法命名应表达业务语义：should_return_xxx_when_yyy。
6. Mock 边界：只 Mock 外部依赖（DB/RPC），被测类自身逻辑禁止 Mock。
7. 一个测试方法只验证一个行为点；断言必须明确，禁止无断言测试。
8. 测试代码与生产代码同等质量要求：遵循命名、格式、注释规约。

--------------------------------------------------------------------------------
十一、工程结构（project-structure.md）
--------------------------------------------------------------------------------
1. 应用层分为：web（controller）/ service / manager / dao 四层。
   - controller：参数校验、转换，不含业务逻辑。
   - service：核心业务逻辑，对业务知识负责。
   - manager：通用能力封装（如发券、鉴权），可被多 service 复用。
   - dao：数据访问，与持久层交互。
2. 跨模块交互通过接口契约，禁止跨层直接调用实现类。

--------------------------------------------------------------------------------
十二、JDK21 专属特性（jdk21-coding-standards/）
--------------------------------------------------------------------------------
1. 虚拟线程：IO 密集型任务优先用 Thread.ofVirtual()，禁止虚拟线程做 CPU 密集计算。
2. 模式匹配：用 instanceof 模式匹配替代冗余类型转换。
3. Record：不可变数据载体优先用 record，替代全字段 Lombok @Data POJO。
4. 结构化并发：多任务并行取结果可使用 StructuredTaskScope，注意预览特性兼容性。
