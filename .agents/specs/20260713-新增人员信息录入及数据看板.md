# 需求规格文档：人员信息录入及数据看板

**文档编号**: 20260713-人员信息录入及数据看板  
**创建日期**: 2026-07-13  
**项目**: my-spring-boot-app  
**技术栈**: Spring Boot 2.6.6 + JPA + H2 + Thymeleaf  

---

## 一、需求概述

新增人员信息管理模块，包含人员信息录入（CRUD）和数据看板两个核心功能模块。

### 核心功能
1. **人员信息录入**：支持人员信息的增加、删除、修改、查询
2. **数据看板**：按岗位维度和职级维度展示统计数据，支持导出

---

## 二、人员信息录入模块

### 2.1 数据模型设计

**实体名称**: `Person`

| 字段名 | 数据类型 | 必填 | 说明 | 示例值 |
|--------|----------|------|------|--------|
| id | Long | 自动生成 | 主键ID | 1 |
| name | String(100) | ✓ | 人员姓名 | 张三 |
| position | String(50) | ✓ | 岗位 | Java开发工程师 |
| level | String(20) | ✓ | 职级 | P5 |
| age | Integer | ✓ | 年龄 | 28 |
| baseLocation | String(100) | ✓ | Base地 | 北京 |
| status | Enum | ✓ | 人员状态 | ACTIVE / INACTIVE |
| createdAt | LocalDateTime | 自动生成 | 创建时间 | 2026-07-13 10:00:00 |
| updatedAt | LocalDateTime | 自动更新 | 更新时间 | 2026-07-13 10:00:00 |

**人员状态枚举**:
- `ACTIVE`: 在职
- `INACTIVE`: 离职

### 2.2 功能清单

#### 2.2.1 新增人员信息
- **入口**: `/persons/new` (GET: 表单页面) + `/persons` (POST: 提交数据)
- **输入项**: 姓名、岗位、职级、年龄、Base地、人员状态
- **校验规则**:
  - 姓名：必填，长度1-100字符
  - 岗位：必填，长度1-50字符
  - 职级：必填，长度1-20字符
  - 年龄：必填，整数，范围18-70
  - Base地：必填，长度1-100字符
  - 状态：必填，枚举值
- **成功响应**: 跳转到人员列表页，显示成功提示
- **失败响应**: 返回表单页，显示错误信息

#### 2.2.2 查询人员列表
- **入口**: `/persons` (GET)
- **查询条件**:
  - 姓名（模糊查询）
  - 岗位（精确匹配）
  - 职级（精确匹配）
  - 状态（精确匹配）
- **排序**: 默认按创建时间倒序
- **分页**: 每页20条记录
- **展示字段**: 姓名、岗位、职级、年龄、Base地、状态、创建时间

#### 2.2.3 修改人员信息
- **入口**: `/persons/{id}/edit` (GET: 表单页面) + `/persons/{id}` (PUT: 更新数据)
- **权限**: 只能修改已存在的人员记录
- **校验规则**: 同新增
- **成功响应**: 跳转到人员列表页，显示成功提示

#### 2.2.4 删除人员信息
- **入口**: `/persons/{id}` (DELETE)
- **确认机制**: 前端弹窗确认
- **成功响应**: 返回人员列表页，显示成功提示

## 三、人员白名单模块

### 3.1 功能概述

人员白名单用于预先登记允许录入系统的人员信息，只有白名单中的人员才能被正式录入到系统中。

### 3.2 数据模型设计

**实体名称**: `PersonWhitelist`

| 字段名 | 数据类型 | 必填 | 说明 | 示例值 |
|--------|----------|------|------|--------|
| id | Long | 自动生成 | 主键ID | 1 |
| name | String(100) | ✓ | 人员姓名 | 张三 |
| idNumber | String(18) | ✓ | 身份证号 | 110101199001011234 |
| phone | String(11) | 否 | 手机号 | 13800138000 |
| position | String(50) | 否 | 预设岗位 | Java开发工程师 |
| level | String(20) | 否 | 预设职级 | P5 |
| status | Enum | ✓ | 白名单状态 | PENDING / USED / EXPIRED |
| createdAt | LocalDateTime | 自动生成 | 创建时间 | 2026-07-13 10:00:00 |
| updatedAt | LocalDateTime | 自动更新 | 更新时间 | 2026-07-13 10:00:00 |

**白名单状态枚举**:
- `PENDING`: 待使用
- `USED`: 已使用（人员已录入）
- `EXPIRED`: 已过期

### 3.3 功能清单

#### 3.3.1 新增白名单
- **入口**: `/whitelist/new` (GET) + `/whitelist` (POST)
- **输入项**: 姓名（必填）、身份证号（必填）、手机号、预设岗位、预设职级
- **校验规则**:
  - 身份证号：18位，符合身份证格式校验
  - 手机号：11位数字
  - 身份证号唯一性校验
- **成功响应**: 返回白名单列表页

#### 3.3.2 查询白名单
- **入口**: `/whitelist` (GET)
- **查询条件**: 姓名、身份证号、状态
- **分页**: 每页20条

#### 3.3.3 修改白名单
- **入口**: `/whitelist/{id}/edit` (GET) + `/whitelist/{id}` (PUT)
- **约束**: 仅 `PENDING` 状态可修改

#### 3.3.4 删除白名单
- **入口**: `/whitelist/{id}` (DELETE)
- **约束**: 仅 `PENDING` 状态可删除

#### 3.3.5 白名单验证
- **触发时机**: 新增人员信息时
- **验证逻辑**: 根据身份证号匹配白名单
- **验证结果**:
  - 匹配成功：允许录入，白名单状态变更为 `USED`
  - 匹配失败：拒绝录入，提示"人员不在白名单中"

#### 3.3.6 批量导入
- **入口**: `/whitelist/import` (POST)
- **文件格式**: Excel (.xlsx)
- **导入字段**: 姓名、身份证号、手机号、预设岗位、预设职级
- **处理逻辑**: 跳过重复身份证号，返回导入结果统计

### 3.4 接口定义

#### 3.4.1 查询白名单列表
```
GET /api/whitelist
```

**请求参数**:
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| name | String | 否 | 姓名 |
| idNumber | String | 否 | 身份证号 |
| status | String | 否 | 状态 |

#### 3.4.2 新增白名单
```
POST /api/whitelist
```

**请求体**:
```json
{
  "name": "张三",
  "idNumber": "110101199001011234",
  "phone": "13800138000",
  "position": "Java开发工程师",
  "level": "P5"
}
```

#### 3.4.3 批量导入
```
POST /api/whitelist/import
```

**请求**: `multipart/form-data` 文件上传

**响应示例**:
```json
{
  "total": 100,
  "success": 95,
  "duplicated": 5,
  "failed": 0
}
```

## 四、数据看板模块

### 4.1 功能概述

提供两个维度的统计数据展示，并支持导出为 Excel 文件。

### 4.2 岗位维度统计

**入口**: `/dashboard/position`

**统计维度**: 按岗位分组统计

**统计指标**:
- 各岗位人员总数
- 在职人员数
- 离职人员数
- 平均年龄
- 各职级分布（子表）

**展示形式**:
- 统计表格（主视图）
- 柱状图（可选，前端图表库）

### 4.3 职级维度统计

**入口**: `/dashboard/level`

**统计维度**: 按职级分组统计

**统计指标**:
- 各职级人员总数
- 在职人员数
- 离职人员数
- 平均年龄
- 各岗位分布（子表）

**展示形式**:
- 统计表格（主视图）
- 饼图（可选，前端图表库）

### 4.4 导出功能

#### 4.4.1 导出接口
- **岗位维度导出**: `/dashboard/position/export` (GET)
- **职级维度导出**: `/dashboard/level/export` (GET)

#### 4.4.2 导出规格
- **文件格式**: Excel (.xlsx)
- **文件命名**: `{维度}_{日期}.xlsx` (例: `position_20260713.xlsx`)
- **技术实现**: Apache POI 库
- **数据范围**: 导出当前查询条件下的所有数据（不分页）

## 十、风险与约束

### 9.1 已知风险
1. **数据量风险**: 当人员数量超过 10 万条时，统计查询可能需要优化（添加缓存）
2. **导出性能**: 大数据量导出可能导致内存溢出，需限制单次导出数量

### 9.2 技术约束
1. 当前使用 H2 内存数据库，重启后数据丢失（生产环境需切换到持久化数据库）
2. 未涉及权限控制，所有用户均可访问所有功能

### 9.3 假设条件
1. 假设岗位和职级为自由文本输入，暂不要求预设字典表
2. 假设 Base 地为自由文本输入，暂不做地理位置关联
3. 假设无需历史记录追溯（修改/删除后原数据丢失）
