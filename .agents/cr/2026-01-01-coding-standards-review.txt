--------------------------------------------------------------------------------
一、命名规范检查
--------------------------------------------------------------------------------
[ ] 类名是否使用大驼峰命名法（UpperCamelCase）
[ ] 方法名、参数名、成员变量、局部变量是否使用小驼峰命名法
[ ] 常量名是否全大写且单词间用下划线分隔
[ ] 包名是否统一使用小写且符合语义规范

--------------------------------------------------------------------------------
二、代码格式检查
--------------------------------------------------------------------------------
[ ] 大括号使用是否符合规范（左括号前不换行，后换行）
[ ] 缩进是否使用4个空格（无Tab字符）
[ ] 单行字符数是否不超过120个
[ ] 小括号与相邻字符间是否无多余空格

--------------------------------------------------------------------------------
三、异常日志检查
--------------------------------------------------------------------------------
[ ] 是否使用SLF4J作为日志框架
[ ] 是否使用占位符方式记录日志
[ ] 异常类命名是否以Exception结尾
[ ] 是否避免使用e.printStackTrace()
[ ] 业务异常是否使用自定义异常类

--------------------------------------------------------------------------------
四、安全规范检查
--------------------------------------------------------------------------------
[ ] 所有用户输入是否进行验证
[ ] SQL语句是否使用参数化查询
[ ] 敏感数据传输是否加密
[ ] 日志中是否避免打印敏感信息

--------------------------------------------------------------------------------
五、数据库规范检查
--------------------------------------------------------------------------------
[ ] 表名、字段名是否使用小写字母或数字
[ ] 表是否包含必备字段：id, create_time, update_time
[ ] 是否禁止使用存储过程
[ ] 是否使用resultMap映射查询结果

--------------------------------------------------------------------------------
六、单元测试检查
--------------------------------------------------------------------------------
[ ] 是否遵循FIRST原则
[ ] 测试方法命名是否采用should_xxx_when_xxx格式
[ ] 测试代码是否遵循AAA模式
[ ] 业务代码修改时是否同步更新单元测试

--------------------------------------------------------------------------------
七、并发处理检查
--------------------------------------------------------------------------------
[ ] 获取单例对象是否保证线程安全
[ ] 线程池是否通过ThreadPoolExecutor创建
[ ] 并发修改场景是否使用线程安全集合或加锁
[ ] 锁范围是否尽可能小

--------------------------------------------------------------------------------
八、集合处理检查
--------------------------------------------------------------------------------
[ ] 覆写equals方法是否同时覆写hashCode方法
[ ] 集合转数组是否使用toArray(T[] array)方法
[ ] 是否使用泛型避免强制类型转换
[ ] 是否避免在循环中进行数据库操作

--------------------------------------------------------------------------------
九、OOP规范检查
--------------------------------------------------------------------------------
[ ] 静态成员是否通过类名访问
[ ] 是否避免使用可变参数
[ ] 外部依赖接口是否禁止修改方法签名
[ ] 所有覆写方法是否加@Override注解

--------------------------------------------------------------------------------
十、注释规范检查
--------------------------------------------------------------------------------
[ ] 类、类属性、类方法注释是否使用Javadoc规范
[ ] 所有抽象方法是否使用Javadoc注释
[ ] 方法内部注释是否符合规范（单行//，多行/* */）
[ ] 注释内容是否准确表达代码意图

P2 - 参考：可选改进（代码风格优化）
