数科业务 Java 编码规范要点概述
========================================

一、命名规范
1. 类名使用大驼峰命名法（UpperCamelCase）
2. 方法名、参数名、成员变量、局部变量使用小驼峰命名法（lowerCamelCase）
3. 常量名全大写，单词间用下划线分隔
4. 包名统一使用小写，点分隔符之间有且仅有一个自然语义的英语单词

二、代码格式
1. 大括号使用规范：左大括号前不换行，左大括号后换行，右大括号前换行
2. 缩进使用4个空格，禁止使用Tab字符
3. 单行字符数限制不超过120个，超出需要换行
4. 左小括号和右边相邻字符之间不出现空格，右小括号和左边相邻字符之间不出现空格

三、异常日志
1. 使用SLF4J作为日志框架，使用占位符方式记录日志
2. 异常类命名以Exception结尾，错误码需快速溯源
3. 捕获异常后不要直接使用e.printStackTrace()，应记录日志
4. 业务异常使用自定义异常类，不要直接抛出RuntimeException

四、安全规范
1. 所有用户输入必须进行验证
2. SQL语句使用参数化查询，禁止拼接SQL
3. 敏感数据传输需加密，禁止明文传输
4. 避免在日志中打印敏感信息

五、数据库规范
1. 表名、字段名使用小写字母或数字
2. 表必备字段：id, create_time, update_time
3. 禁止使用存储过程，存储过程难以调试和扩展
4. 使用resultMap映射查询结果

六、单元测试
1. 遵循FIRST原则：Fast, Independent, Repeatable, Self-validating, Timely
2. 测试方法命名采用should_xxx_when_xxx格式
3. 测试代码遵循AAA模式：Arrange, Act, Assert
4. 业务代码修改时同步更新单元测试

七、并发处理
1. 获取单例对象需要保证线程安全
2. 线程池通过ThreadPoolExecutor创建，禁止Executors创建
3. 并发修改场景使用线程安全集合或加锁
4. 锁范围尽可能小，避免性能问题

八、集合处理
1. 覆写equals方法必须同时覆写hashCode方法
2. 集合转数组使用toArray(T[] array)方法
3. 使用泛型避免强制类型转换
4. 避免在循环中进行数据库操作

九、OOP规范
1. 静态成员通过类名访问，不通过对象引用访问
2. 避免使用可变参数
3. 外部正在调用或依赖的接口，禁止修改方法签名
4. 所有覆写方法必须加@Override注解

十、注释规范
1. 类、类属性、类方法注释使用Javadoc规范
2. 所有抽象方法必须使用Javadoc注释
3. 方法内部单行注释使用//，多行注释使用/* */
4. 注释内容准确表达代码意图，无歧义
