# Spec: 快捷 Copy 与快捷 Delete 文件

## Feature: 快捷 Copy 物品

### Scenario: 从列表页复制一个已有物品
- **Given** 用户在物品列表页（`/items`），列表中存在至少一个物品
- **When** 用户点击某个物品行旁的"复制"按钮
- **Then** 系统创建一个该物品的副本（保留名称、描述、分类、价格、数量等字段，重置 ID、createdAt、updatedAt）
- **And** 跳转到物品编辑页（`/items/{newId}/edit`），显示成功提示"物品复制成功，请修改后保存"
- **And** 副本尚未持久化到数据库，待用户编辑后点击保存时才写入

### Scenario: 从详情页复制一个物品
- **Given** 用户在物品详情页（`/items/{id}`）
- **When** 用户点击页面上的"复制"按钮
- **Then** 系统行为与列表页复制一致：创建副本并跳转编辑页

### Scenario: 复制不存在的物品
- **Given** 用户尝试复制一个 ID 不存在的物品
- **When** 请求到达服务端
- **Then** 系统返回错误提示"物品不存在，无法复制"
- **And** 重定向回物品列表页

## Feature: 快捷 Delete 物品

### Scenario: 从列表页快捷删除一个物品
- **Given** 用户在物品列表页（`/items`），列表中存在至少一个物品
- **When** 用户点击某个物品行旁的"快捷删除"按钮
- **Then** 系统直接删除该物品
- **And** 刷新列表页，显示成功提示"物品删除成功！"
- **And** 被删除的物品不再出现在列表中

### Scenario: 快捷删除不存在的物品
- **Given** 用户尝试删除一个 ID 不存在的物品
- **When** 请求到达服务端
- **Then** 系统返回错误提示"物品不存在，删除失败"
- **And** 重定向回物品列表页

## Edge Cases
- 列表页为空时，不显示复制和删除按钮（因为没有物品行）。
- 复制操作仅做内存拷贝，不立即持久化，避免产生"孤儿"副本。
- 删除操作沿用现有 `ItemService.deleteById()` 的校验逻辑（如检查物品是否存在）。
